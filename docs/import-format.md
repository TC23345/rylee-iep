# Case log import format

The case log imports Excel workbooks laid out the way Rylee kept hers by hand.
Three reference files live in `docs/import-samples/` (July, August and
September 2026, synthetic data modelled on her real 8/17 day). They are
regenerated by `node scripts/make-sample-workbooks.mjs`. When converting one of
her own unstructured spreadsheets, produce a file that matches these exactly.

## Workbook

One `.xlsx` per month is the convention, but a workbook may hold several month
sheets; every sheet that has the header below is imported.

| Sheet | Purpose | Imported? |
|---|---|---|
| `Daily Case Counts` | `Date`, `Case Count`. One row per logged day. | No. Counts are derived from the rows, so this sheet is skipped. Keep it for her reference. |
| `August_2026` (one per month, named `<Month>_<Year>`) | The log rows. | Yes |

Any sheet whose name contains "daily case counts" (case-insensitive) is skipped.
Any other sheet is imported if a header row can be found in its first ten rows.

## Month sheet columns

The header row must contain, in any order, cells matching these names. Matching
is case-insensitive and looks for the key words shown.

| Column | Header must contain | Cell contents |
|---|---|---|
| Date | starts with `Date` | An Excel date (preferred), or text like `8/17/2026`, `8/17/26`, `2026-08-17`. **Written on the first row of each day only**; the rows beneath leave it blank and inherit it. |
| Case number | `Case #`, `Case No`, or `Case Number` | Digits, as a number or text. Blank for Lunch, Meeting, Admin Tasks, and Phone Call rows that were not about a case. |
| Case type | contains `Type` | One of the eleven types below. |
| Start | contains `Start` | An Excel time (preferred), or text like `9:12 AM` or `09:12`. |
| End | contains `End` | Same as Start. |
| Duration | anything, typically `Duration` | Ignored; the app recomputes length from Start and End. Fill it in for her, as a time cell formatted `h:mm`. |
| Notes | contains `Note` | Free text, blank allowed. |

Rows that are entirely blank are skipped. A row with a date cell that cannot be
read, or a type that is not in the list, is reported in the import dialog and
left out; everything else in the file still imports.

## Case types

Exactly these labels (matching is case-insensitive and ignores punctuation, so
`recon reply` and `RECON REPLY` both work):

| Label | Counts as a case? | Case number |
|---|---|---|
| Reconsideration | yes | required |
| Recon Reply | yes | required |
| Continuation | yes | required |
| BCBA Reply | yes | required |
| Authorization Revision | yes | required |
| Additional Info | yes | required |
| Initial | yes | required |
| Phone Call | only when a case number is given | optional |
| Meeting | only when a case number is given | optional |
| Admin Tasks | only when a case number is given | optional |
| Lunch | never | leave blank |

Accepted aliases: `Lunch / break` and `Break` → Lunch, `Recon` →
Reconsideration, `Auth Revision` → Authorization Revision, `Phone` → Phone
Call, `Admin` → Admin Tasks.

## Dedupe

A row already in the log with the same day, case number and start time is
skipped, so importing the same file twice, or a corrected copy, is safe. Rows
whose times changed will import as new rows; delete the old ones in the app.

## Checklist for a converted file

1. One sheet per month named `<Month>_<Year>`, plus a `Daily Case Counts` sheet.
2. Header row exactly: `Date | Case # | Case Type | Start Time | End Time | Duration | Notes`.
3. Date on the first row of each day only.
4. Real Excel date and time cells, not text, wherever possible.
5. Types spelled as listed above.
6. Case numbers are digits only.
